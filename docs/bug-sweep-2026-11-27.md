# Bug sweep of the C code (2026-11-27)

A sweep of `src/*.c` (85 files, about 50,000 lines) at commit `87ae1df`, vo 0.7.0. Vendored code under
`third_party/` and the generated tree-sitter parser were not reviewed.

**Result: 38 findings.** 2 Critical, 7 High, 11 Medium, 18 Low. Findings 1 to 9 (every Critical and High
one) are fixed; see [Status](#status). 10 to 38 are open.

- Both Critical findings and four of the High ones (3, 4, 5, 7) let checked vo code, or a hostile input file, corrupt
  or crash the toolchain.
- Two High findings break the effects boundary of [security.md](security.md): one deletes directories
  named by a hostile `vo.packages`, one lets a file read escape its grant through a symlink race.
- One High finding lets a remote client stop any vo server.

## How it was done

- **Seven reviewers** each read one group of files and reproduced what they found with `build/vo`. They
  changed nothing in the repository and rebuilt nothing.
- **`gcc -fanalyzer`** (GCC 13.3) ran over every file with the flags of `make lint-c`. It reported 8
  null dereferences; all 8 are false positives with one cause (finding 38).
- **Status** of each finding is *reproduced* (a program or input was run and misbehaved) or *by reading*
  (3 findings). 34 are reproduced; finding 38 is the analyzer's.
- **Checked a second time when the reports were merged:** findings 1, 2 and 4 were re-run; the cited
  code of 3, 5, 6, 7 and 14 was read. The rest stand on the reviewer's reproduction.
- Findings already listed in [security-review-1.md](security-review-1.md) or
  [review-2026-11/inconsistencies.md](review-2026-11/inconsistencies.md) were left out.

Line numbers are those of `87ae1df`.

## Root causes

Several findings share a cause; fixing the cause fixes the group.

| Cause | Findings | Fix direction |
|---|---|---|
| C state read again after a vo callback ran | 1, 3, 4 | read into a rooted local before the callback; no globals across `call_value` |
| `write_all` discards the result of the write | 10, 11 | callers that report success use `write_checked` |
| A path taken from a file, or checked and then opened by its text | 6, 9, 13, 27, 28, 33 | open with `O_NOFOLLOW` from a checked directory fd; never follow manifest paths outside `packages/` |
| A resource held across a jump out of the function (`rt_timeout`, `rt_raise`) | 17, 32 | close before raising, as `tls_exchange` does |
| A walk over types with no depth limit | 19 | the limit the sibling walkers already have |
| Fixed-size table with no bound check | 3, 5 | check before the write |

## Critical

### 1. `filter` reads outside the list when its callback shrinks it

- **Where:** `src/rt_func.c:33` (`hof_filter`).
- **Defect:** the loop reads `list->data[i]` again after `call_value` returns, without checking the
  list's length or buffer again. This is the class of C4 (`sort_by`) in the first security review;
  `filter` was not fixed with it.
- **Failure:** the callback pops the list and calls `sort`, which gives it a smaller buffer. `filter`
  then pushes a heap word from outside that buffer into its result as an element. vo code holds a forged
  object.
- **Repro:**
  ```vo
  fn main() uses console {
      let xs = new list[str];
      for i in 0..2000 { push(xs, "item " + str(i)); }
      let out = filter(xs, fn(x) {
          if x == "item 1500" {
              while len(xs) > 2 { match pop(xs) { case ok(v) { } case err(e) { } } }
              sort(xs);
              let pad = new list[int];
              for k in 0..3000 { push(pad, k * 1000003); }
          }
          return true;
      });
      print(str(len(out)));
      print(str(len(out[len(out) - 1])));
  }
  ```
  Prints `1501`, then `68719552832` as the length of a string. Printing the string dumps heap memory.
- **Fix:** copy the element into a rooted local before the callback and push the copy:
  `long x = list->data[i].i; GC_ROOT(&x); if (call_value(fn, call, &x)) list_push(out, x);`.

### 2. `set` on a function name is accepted and overwrites a local slot

- **Where:** `src/check.c:629-664` (`check_set`); the cause is in `src/check_expr.c:759-763`.
- **Defect:** `check_set` rejects constants and immutable locals only. A function name passes
  `check_place`. Its node has no slot (`c.i` is 0), so the assignment writes the closure into slot 0 of
  the current frame.
- **Failure:** pure, checked code gets type confusion and a segfault. `set m.f = ...` takes the same
  path.
- **Repro:**
  ```vo
  fn double(x: int) -> int { return x * 2; }
  fn triple(x: int) -> int { return x * 3; }
  fn main() uses console { let n = 5; set double = triple; print(str(n)); }
  ```
  `vo check`: 0 errors. `vo run` prints `154618839096` (a pointer) for `n`. With
  `let xs = [1, 2, 3]; set double = fn(x) => x + 1; print(str(xs[100000]));` the run segfaults.
- **Fix:** in `check_set`, report E0208 when the place is a name that is not a local.

## High

### 3. The comparison guard breaks after 32 nested comparisons

- **Where:** `src/rt_coll.c:87-89` (`ccmp`).
- **Defect:** `coll_active[coll_nactive++] = c` runs only while `coll_nactive < 32`, but
  `coll_nactive--` always runs. Deeper nesting drives the counter negative. The next call writes before
  the array, onto `coll_nactive` itself and the recording's file buffer, and `coll_check_change` checks
  nothing while the counter is negative.
- **Failure:** after a comparison function has nested 40 deep, another collection's comparison function
  can change its own collection without R0007. That is the change the guard exists to stop, and it can
  become a use-after-free in `tree_put` and `heap_less`. Under `--record` the run segfaults.
- **Repro:** an `ordered_set_by` whose comparison function calls `has` on its own set while a depth
  counter is below 40; then a second set whose comparison function pushes into that second set. Without
  the nesting: R0007. With it: the push succeeds and the program exits 0.
- **Fix:** decrement only when this call pushed, or raise R0005 past 32 levels.

### 4. `sort_by` segfaults when its key function sorts another record type

- **Where:** `src/rt_func.c:99` (`hof_sort_by`); the global is at `src/rt_list.c:91`.
- **Defect:** `elem_record_type` is set before the key function runs and read by the merge afterwards.
  A `sort`, `min`, `max` or `sort_by` inside the key function overwrites it. The comment at
  `rt_list.c:89` says record comparison runs no vo code, which does not hold for `sort_by`.
- **Repro:**
  ```vo
  record Key { n: int; }
  record Name { s: str; }
  fn main() uses console {
      let xs = [3, 1, 2];
      let names = [new Name { s: "b" }, new Name { s: "a" }];
      sort_by(xs, fn(x) { sort(names); return new Key { n: x * 1000003 }; });
      print(str(xs[0]) + " " + str(xs[1]) + " " + str(xs[2]));
  }
  ```
  Segmentation fault, exit 139. With an inner sort of ints the keys are ordered by address instead.
- **Fix:** set `elem_record_type` after the key loop, just before the merge; better, pass the type to
  `elem_less` and `hof_merge` and drop the global.

### 5. A program of more than 256 files overflows the file table

- **Where:** `src/diag.c:20-22` (`file_add`); `MAX_FILES` is 256 (`vo.h:206`).
- **Defect:** `file_table[file_count++]` is written with no check, and no caller checks either.
- **Failure:** a program of 257 files, counting the std modules it imports, corrupts the globals after
  the table. `vo check`, `run`, `test`, `query`, `lsp` and `mcp` segfault. `vo edit` registers each file
  twice and reaches the limit at half the size.
- **Repro:** `main.vo` importing `m1` to `m256`, each `export fn f() -> int { return K; }`. With 255
  imports `vo check` exits 0; with 256 it segfaults.
- **Fix:** a toolchain error in `file_add` when the table is full, or a table that grows.

### 6. A hostile `vo.packages` makes `vo package --repair` delete any directory

- **Where:** `src/packages.c:1696-1699`; the same trust is behind `sel_apply` (1667-1706) and
  `pkg_restore` (1926-1947).
- **Defect:** a versioned entry's directory is taken from the manifest and may be `.`, `..` or an
  absolute path. When the entry is dropped, `rm_tree` removes that directory. The only guard,
  `pkg_intact`, hashes `.vo` files, which the author of the manifest controls.
- **Failure:** a cloned repository carries the line
  `money . sha256:<hash of its own .vo files> https://example.invalid/acme/money@1.0.0 indirect`.
  `vo package --repair main.vo` (the command E0709 suggests) prints `removed money 1.0.0`, exits 0, and
  the project directory is empty, `.git` included. `--remove` does the same. No network is needed.
- **Fix:** remove or replace only directories under `<manifest dir>/packages/`; refuse (E0703) a
  versioned entry whose directory is outside the manifest's directory, or contains it.

### 7. A hostile recording crashes `vo replay`

- **Where:** `src/replay.c:1238-1240` (`rp_check_event`); the null value is used at `src/tcp.c:201-203`,
  313, 396, 453, 480 and 543, and in `rp_result` at `src/process.c:736`.
- **Defect:** for kinds from `EVK_INFO` up, a `denied` result returns before the value is checked. Only
  `io_replay` and `fs.c` refuse `denied`; `tcp.c` dereferences the missing value.
- **Repro:** a recording holding `{"v":1,"kind":"tcp_open","name":"127.0.0.1:9","result":"denied"}`,
  replayed against a program that calls `tcp.connect("127.0.0.1", 9, 500)`: segmentation fault.
- **Fix:** accept `denied` only for the kinds that handle it; refuse it (T0008) for `tcp_*`, `proc_*`,
  `file_block` and worker events.

### 8. About 60 header-only requests make a server exit

- **Where:** `src/serve.c:345-351` (`conn_read`).
- **Defect:** when a request's head arrives, the connection gets a buffer of head plus Content-Length
  (up to 16 MiB) before any body byte arrives. Nothing limits the total over the 64 connections, and the
  allocation is outside the handler guard.
- **Failure:** a client opens connections that each send
  `POST / HTTP/1.1\r\nHost: x\r\nContent-Length: 16000000\r\n\r\n` and wait. The server ends with R0006,
  exit 70. 60 connections do it at the default 512 MiB; 5 do it under `--max-memory 64`. The parent of
  `serve_workers` is hit the same way.
- **Fix:** grow the buffer with the bytes received; cap the total buffered over all connections and
  answer 503 above it.

### 9. A symlink swap lets a file access escape the root grant

- **Where:** `src/rt_effects.c:625-640` (`open_parent`, also used by `rt_open_file`).
- **Defect:** a scoped access starts from the deepest scope that holds the path and opens that scope by
  its unresolved text, which follows links. Only the components after the scope are walked with
  `O_NOFOLLOW`. This is the H4 class that spec 013 closed for the root scope.
- **Failure:** `main` declares `file.read("data/")`; a helper declares `file.read("data/sub/")` and
  reads `data/sub/x`. A local process exchanges `data/sub` with a link to `../outside`. The check sees
  the real directory, the open follows the link.
- **Repro:** with the exchange running in a loop, 24 of 400 runs printed the contents of `outside/x`.
  The same read with only the `"data/"` scope never did.
- **Fix:** walk the resolved path with `O_NOFOLLOW` from the outermost granting directory, or compare
  the opened scope's identity with the resolved directory.

## Medium

### 10. `write_file` returns ok when the write fails

- **Where:** `src/rt_io.c:120`; the cause is `write_all` at `src/sys.c:200`.
- **Defect:** `write_all` discards the failure of `write_checked`. `std.fs.write_bytes` takes the same
  path.
- **Repro:** `write_file("/dev/full", "hello")` returns `ok`; `fs.append_file` on the same path returns
  `err no space left`.
- **Fix:** `write_checked` in `rt_write_file`, with the error text `fs_err` gives.

### 11. `vo fmt` can truncate a source file and exit 0

- **Where:** `src/main.c:763-767` (`write_file_safely`).
- **Defect:** the results of `write_all`, `sys_close` and `sys_rename` are not checked, a failed
  `open_tmp` returns silently, and the temporary file is always created 0644.
- **Failure:**
  - under a file-size limit or a full disk, an 8319-byte file is replaced by its first 4096 bytes; vo
    prints `formatted big.vo` and exits 0;
  - in a read-only directory vo prints `formatted` and changes nothing;
  - a 0600 file becomes 0644;
  - `vo package` and `effects --update` write through the same function.
- **Fix:** check each step, unlink the temporary file and fail with T0009 as `build.c` does; `fchmod`
  the temporary file to the original's mode.

### 12. A generic function's own scope is not enforced at run time

- **Where:** `src/types.c:548-560` (`rt_es_grant`), used at `src/vm.c:110` and 721.
- **Defect:** a function with effect parameters runs with the union of its declaration and its caller's
  grant, and `es_union` drops scopes when either side is unscoped. The function's own scope is lost.
- **Failure:** `fn g[E: effects](p: str, f: fn() uses E) -> str uses E, file.read("a/")` reads
  `secret.txt` when its caller declares `file.read`. A function with the same declaration and no effect
  parameter gets R0010. The root grant still bounds the access.
- **Fix:** keep the function's own scoped declaration as a separate grant checked when its own body
  performs the effect; the union stays for what it calls.

### 13. `vo test --record` writes through a planted symlink

- **Where:** `src/replay.c:1590-1600` (`rt_begin`).
- **Defect:** the temporary file has the fixed name `DIR/.recording.tmp` and is opened following links
  and truncating. This is the M3 class, fixed for `fmt` and `edit`. Recordings are committed, so a
  hostile repository controls `DIR`.
- **Repro:** with `recs/.recording.tmp -> ../../victim.txt`, `vo test --record recs t.vo` replaces
  `victim.txt` with recording lines.
- **Fix:** `tmp_path` and `open_tmp`, as the other writers use.

### 14. `vo edit rename` rewrites package and std files

- **Where:** `src/edit.c:141-148` (`ed_rename`), written by `ed_write_all` at 582.
- **Defect:** a change is added at every reference, including those in package and std files.
- **Failure:** renaming a package's function rewrites the pinned package and exits 0; the next `vo run`
  fails with E0701. Renaming a std function lists changes to `std/text.vo`.
- **Fix:** refuse (T0006) a rename whose declaration or references lie in a library file
  (`file_is_library`).

### 15. `@size` error message built from unrooted strings

- **Where:** `src/json_derive.c:445-446` (`check_limits`).
- **Defect:** `msg(..., int_to_str(lo), str_from_cstr(unit), int_to_str(n))` allocates in each argument
  while the earlier results are held only in registers.
- **Repro:** `from_json` into a record with `@size(2, 3) name: str`, given a 10-character name.
  `build/vo` prints `at most 3 characters, got 10`; `VO_GC_STRESS=1 build-stress/vo` prints
  `at most 3 3s, got 3`.
- **Fix:** build the three strings into rooted locals first.

### 16. Two valid patterns in one process end it with R0006

- **Where:** `src/regex.c:848-865` (`ensure_vm`).
- **Defect:** the thread and slot capacities each grow to their own maximum, and the capture buffer is
  their product. The per-pattern limit bounds each pattern alone.
- **Repro:** `is_match("b", regex("(?:a{1000}){17}"))` followed by
  `is_match("b", parse_regex(text.repeat("()", 700)))` ends with R0006. The second pattern alone prints
  `true`. A server that compiles patterns from clients can be stopped this way.
- **Fix:** size the buffer from the current pattern's threads times slots.

### 17. An HTTP call that times out in a handler leaks a socket

- **Where:** `src/net.c:286`, 316 and 335 (`net_open`, `rt_http_exchange`), and the DNS socket at 199.
- **Defect:** `net_wait` calls `rt_timeout` and leaves the function with the socket open. `tls_exchange`
  closes first; the plain path does not.
- **Repro:** a server run with `--timeout 1` whose handler calls `http.get` on a peer that never
  answers: 5 requests raise the open descriptors from 6 to 11.
- **Related, by reading:** a handler that fails while holding a `std.tcp` connection or TLS session
  leaves its table entry for good; after 256 of them every open returns `too_many`.
- **Fix:** close before every `rt_timeout` in `net.c`; sweep the tcp entries a failed handler opened.

### 18. `tcp.close_listener` passes the checker and fails with R0010

- **Where:** `src/tcp.c:606`.
- **Defect:** `OP_CLOSE` and `OP_CLOSE_LISTENER` call `rt_check_effect`, but `std/tcp.vo:254` declares
  `close_listener` with no effects (spec 056).
- **Repro:** `fn shut(l: tcp.Listener) { tcp.close_listener(l); }` called from a `main` with
  `serve("0")`. `vo check` reports 0 errors; `vo run` stops with
  ``R0010: serve is not allowed: `shut` declares nothing (pure)``.
- **Fix:** drop the effect check in the close cases.

### 19. The checker hangs on a polymorphically recursive type

- **Where:** `src/check_func.c:363-396` (`task_func_path`); the same in `src/prop.c:101-160`
  (`pg_find`, `pg_finite`).
- **Defect:** the walkers mark visited types by pointer and have no depth limit. For
  `more(N[list[T]])` every level is a new instance. The sibling walkers stop at depth 32 or 64.
- **Repro:**
  ```vo
  variant N[T] { stop; more(N[list[T]]); }
  fn g(x: int) -> N[int] { return N.stop; }
  fn main() uses console { let ys = concurrent_map([1, 2], 2, g); print(str(len(ys))); }
  ```
  `vo check` was still running after 5 minutes. `prop "never" (n: N[int]) { expect(true); }` hangs too.
- **Fix:** a depth limit in the three walkers.

### 20. A property starts with the previous test's log and metrics

- **Where:** `src/testrun.c:648-665` (`run_one_test`) with `src/prop.c:686-700` (`pr_try`).
- **Defect:** `rt_log_reset` and `rt_metrics_reset` run on the path of ordinary tests only.
- **Repro:** a test that logs one record, then a property that logs one record and expects
  `len(log.logged()) == 1`. The property fails with `len(log.logged()): 4` and a counterexample that
  means nothing. The metrics case was read, not run.
- **Fix:** call both resets in `pr_try` beside `rt_effects_start(1)`.

## Low

### 21. `expect_eq` names the wrong character for a multi-byte difference

- **Where:** `src/rt_test.c:298-308` (`expect_eq_diff`).
- **Defect:** the lead byte of a character is counted before its continuation bytes are compared.
- **Repro:** 40 `a` then `é!` against 40 `a` then `è!`: the report says
  `first difference at character 42: expected "!", actual "!"`. The difference is character 41.
- **Fix:** step back to the lead byte before counting.

### 22. A FIFO named like a module hangs `vo check`

- **Where:** `src/loader.c:147` (`import_exists`) and `src/packages.c:479` (`pkg_doc_path`).
- **Defect:** `sys_open(path, O_RDONLY)` without `O_NONBLOCK`; L4 fixed this elsewhere.
- **Repro:** `mkfifo util.vo` beside a file that uses `util.twice(1)`: `vo check` blocks.
- **Fix:** open with `O_PATH` and accept regular files only.

### 23. A program under a directory named `std/` cannot import its own modules

- **Where:** `src/loader.c:66-77` and 114 (`load_file`).
- **Defect:** `std_lookup` runs for any path that starts with `std/`, not only for `import std.*`.
- **Repro:** `std/main.vo` with `import util;` and `std/util.vo` present gives E0205. The same files
  under `other/` run. `import json;` would load the embedded module in place of the local file.
- **Fix:** look in the embedded library only when the import's first segment is `std`.

### 24. A large `--timeout` overflows and times out at once

- **Where:** `src/main.c:289-293`; the multiplications are at `src/interp.c:393`, `testrun.c:649` and
  `serve.c:82` and 660.
- **Repro:** `vo run --timeout 9223372036854775 loop.vo` stops at once with R0009, exit 124.
- **Fix:** bound the option as the other numeric options are bounded.

### 25. The E0214 fix overflows and writes a wrong value

- **Where:** `src/libchange.c:170` (`scaled`).
- **Repro:** `fixed_zone(999999999999999999)` gets the fix `offset_zone(-7258471777171466848`.
- **Fix:** on overflow, write `(LIT) * factor` or attach no fix.

### 26. `vo edit add-field` fails on a one-line record

- **Where:** `src/edit.c:221-228`.
- **Defect:** the field goes at the start of the line after the last field, even when the closing `}`
  is on the same line.
- **Repro:** `record P { x: int; }` and `vo edit add-field m2.vo P y: int = 0`: the field lands after
  the record and the edit is refused with T0006.
- **Fix:** insert before the `}` when it is on the last field's line.

### 27. Package staging directories are predictable and followed

- **Where:** `src/packages.c:1094-1101` (`with_pid`) and 716-731 (`pkg_write_files`).
- **Defect (by reading):** the staging name is `<target>.new-<pid>`, `mkdir_p` accepts a directory that
  exists, and `O_NOFOLLOW` covers the last component only. A local process that creates the name as a
  link first has the fetched files written elsewhere.
- **Fix:** `mkdirat` with a random suffix that fails if the name exists, then `openat` on its fd.

### 28. `vo package` pins a package whose file is a link leading outside it

- **Where:** `src/main.c:161-174` (`walk_dir`, strict mode).
- **Defect:** links to directories are checked; a link to a file is hashed. S8 says such a package is
  refused with E0702.
- **Repro:** `money/calc.vo -> ../outside/real.vo`: `vo package` adds it; `vo run` then fails with
  E0211.
- **Fix:** resolve file links in strict mode and fail when they leave the package.

### 29. JSON floats of more than 19 digits can round the wrong way

- **Where:** `src/json_text.c:191-229` (`jp_float`).
- **Defect:** digits after the 19th are dropped with no record that one was not zero.
- **Repro:** `parse_json("9007199254740993.00000000000000000001")` gives `9007199254740992.0`; the
  correct result is `9007199254740994`.
- **Fix:** when a dropped digit is not zero, append a digit `1` before converting.

### 30. `vo fmt` drops the parentheses around a called function literal

- **Where:** `src/fmt.c:373-394` and 452-455 (`expr_prec`).
- **Repro:** `let y = (fn(x) => x + 1)(3);` becomes `let y = fn(x) => x + 1(3);`. Such a call does not
  pass the checker today (E0342, E0343), so only programs with errors change.
- **Fix:** give `N_LAMBDA` a precedence below a call's.

### 31. A 304 response with a Content-Length is rejected

- **Where:** `src/serve.c:189-197` (`http_frame` for responses).
- **Defect:** the status is not read, so a 1xx, 204 or 304 response is expected to have the body its
  headers describe.
- **Repro:** `HTTP/1.1 304 Not Modified` with `Content-Length: 1234` gives
  `err: malformed response: body shorter than Content-Length`.
- **Fix:** an empty body for 1xx, 204 and 304.

### 32. `start_tls` hitting `--timeout` leaves a closed fd in the table

- **Where:** `src/tcp.c:456` with `src/tls.c:360-362`.
- **Defect (by reading):** `tls_open` closes the descriptor and raises R0009, while the connection
  entry keeps the number. Where R0009 is recovered, a later `close` closes whatever has since taken that
  number.
- **Fix:** clear the entry before raising, or leave the close to the caller.

### 33. `fs.info` follows a link swapped in after the check

- **Where:** `src/fs.c:78`, and `fs_list` at 291-292.
- **Defect (by reading):** after a no-follow stat finds a link, a second stat follows it whether or not
  the grant is scoped. Under a scoped grant, a link swapped between the check and that stat reveals the
  kind and size of a file outside the grant.
- **Fix:** under a scoped grant, check the link's target again, or stat an fd from `rt_open_file`.

### 34. `"/"` means the start directory under an unscoped grant

- **Where:** `src/rt_effects.c:610-618` (`open_parent`).
- **Defect:** trimming a path of slashes only leaves directory `"."` and name `"."`.
- **Repro:** `fs.list_dir("/")` lists the start directory; `fs.list_dir("/etc")` is right. `info`,
  `make_dir`, `delete` and a process's working directory take the same path and were not run.
- **Fix:** directory `"/"` and name `"."` for such a path.

### 35. `sort_by` rejects `bool` and variant keys

- **Where:** `src/check_func.c:486-492`.
- **Defect:** the key check lists int, float, str, bytes, records and `T: ordered`. `<`, `sort`, `min`
  and `max` also take `bool`, variants and `T: key`, and the run time handles them.
- **Repro:** `sort_by(xs, fn(p) => p.ok)` gives E0313 "`bool` is not ordered".
- **Fix:** the test `sort` uses: `is_ordered_type` or `ck_param_order`.

### 36. A record literal can give the same field twice

- **Where:** `src/check_expr.c:1187-1204` (`check_new_record`).
- **Repro:** `new P { x: 1, x: 2 }` passes the checker and gives `x` 2. The reference says every field
  is given once.
- **Fix:** report the repeat when `seen[idx]` is already set.

### 37. An effect parameter can be used as a value type

- **Where:** `src/check.c:485-487` (`resolve_type`).
- **Repro:** `fn f[E: effects](x: E) -> E uses E { return x; }` called as `f(5)` gives E0501 "`main`
  does not declare E", with a fix that writes `E` into `main`. Without `uses E` it checks and runs.
- **Fix:** an error when a parameter bound by `effects` is used as a type.

### 38. Functions that never return are not declared `NORETURN`

- **Where:** `src/vo.h:1882-1883`, 2012 and 2515 (`ed_refuse`, `ed_refuse_arg`, `rt_raise`, `vo_exit`).
- **Defect:** not a bug at run time. The compiler and `gcc -fanalyzer` assume these return, which gave
  all 8 analyzer reports (`check_ops.c:49`, `edit.c:132`, `process.c:606`, `sqlite_rt.c:354`,
  `query.c:1304`, `check_effects.c:749` and 753, `json_derive.c:318`). Each was read and none can
  happen.
- **Fix:** add `NORETURN` where it holds on every path, so the analyzer can be run clean and kept in
  `make lint`.

## Checked and found correct

- **Runtime:** in-place string append under aliasing; integer edge cases (`MIN / -1`, `-MIN`); map
  probing; number formatting and parsing buffers; bytes, hex and base64; the collector's size checks;
  the root stack after a recovery jump.
- **Decoders:** inflate, untar, SHA-1, SHA-256, PBKDF2 and time zones. The regex engine agreed with
  Python's `re` on about 8,000 random pattern and text pairs.
- **Network:** request framing (chunks, trailers, duplicate Content-Length), DNS answers, git pack and
  delta parsing, the libc shims, the SQLite VFS and its grant checks.
- **Checker and effects:** hiding an effect in function values, records, maps, lambdas and contracts;
  constant folding against run time; jumps, `try`, loops and `match` in the compiler; `match`
  exhaustiveness on generic variants.
- **Tools:** LSP framing and UTF-16 positions, the JSON-RPC reader, MCP argument buffers, shrinking
  (bounded), output escaping, the recording reader's other kinds.
