# Ledger: foreign currencies

## The existing program

The program is a double-entry bookkeeping ledger. It reads commands from standard input, one per line, and prints the response to each command. Words on a line are separated by one or more spaces; blank lines are ignored. A *number* is a non-empty string of the digits `0`-`9`; days are numbers. An *amount* is an optional `-`, one or more digits, and optionally `.` followed by one or two digits (`12`, `-3.5`, `0.07`); amounts are held in integer cents and printed as `X.YY` (`-X.YY` when negative): `1250` cents prints `12.50`, `-5` prints `-0.05`. An account name is one or more segments of lower-case letters and digits joined by `:` (`assets:bank`); the accounts *below* `assets` are those whose names start with `assets:`. A transaction ID is lower-case letters and digits. An account's type is one of `asset`, `liability`, `equity`, `income`, `expense`. An account's *balance* is the sum of its postings' amounts.

Commands:

- `open NAME TYPE`: checks the name (`error: bad account name NAME`), the type (`error: bad type TYPE`), that the account does not exist (`error: account NAME exists`), in this order, then prints `opened NAME (TYPE)`.
- `close NAME`: `error: unknown account NAME`, `error: account NAME is closed`, `error: account NAME has balance B` (a non-zero balance), else the account is closed (it stays in all reports; postings and reversals on it are refused) and the program prints `closed NAME`.
- `rename OLD NEW`: `error: unknown account OLD`, `error: bad account name NEW`, `error: account NEW exists`, else the account (with its postings) gets the new name: `renamed OLD to NEW`.
- `post ID DAY DESC SPEC SPEC ...` (DESC a single word, at least two SPECs, each `ACCOUNT=AMOUNT` or `ACCOUNT=`): checks, in this order, the ID (`error: bad id ID`), that it is unused (`error: transaction ID exists`), the lock (`error: books locked through L` when DAY ≤ L), then each SPEC in order: a SPEC without `=` or with a bad amount is `error: bad posting SPEC`, then `error: unknown account NAME`, `error: account NAME is closed`, `error: account NAME posted twice`, and an amount of zero `error: zero posting NAME`. Then more than one `ACCOUNT=` is `error: more than one balancing posting`. An `ACCOUNT=` posting gets minus the sum of the other amounts (`error: zero posting NAME` if that is 0); without one, the amounts must sum to zero, else `error: transaction ID unbalanced by S` (S the sum). Prints `posted ID: N postings, total T`, with T the sum of the positive amounts.
- `void ID DAY`: `error: unknown transaction ID`, `error: transaction ID is a reversal`, `error: transaction ID already voided`, `error: void before day D` (D the transaction's day), the lock error, and `error: account NAME is closed` (first posting in order on a closed account). Else it records the reversal `rev-ID`, dated DAY, description `void:DESC`, with the negated postings in the same order, and prints `voided ID on day DAY`.
- `show ID`: the transaction's line, one line per posting, and the `voided by` / `reverses` lines.
- `lock DAY`: `error: already locked through L` if DAY < L, else the books are locked through DAY: `locked through DAY`.
- `balance NAME`: the sum of the balances of the account NAME (if it exists) and all accounts below NAME: `balance NAME: B`. `error: unknown account NAME` if there are no such accounts.
- `statement NAME` (an existing account): its postings by day (on one day in the order they were entered), with the running balance, in columns, then `  closing balance B`.
- `trial`: per type, the accounts with a non-zero balance, then the total debits (positive balances) and credits (minus the negative ones).
- `income FROM TO`: for the income accounts, then the expense accounts, the sum of their postings dated FROM to TO, and the net income.
- `journal FROM TO`: the transactions dated FROM to TO (by day, then in the order entered) with the sum of their positive amounts.
- `accounts`: every account with its type and balance; `tree`: the account hierarchy with each node's total (the sum of the balances of the account at that node, if any, and all accounts below it).

A command with the wrong number of arguments, or a non-number where a number is required, prints `error: bad command` (checked before anything else). A first word that is not a command prints `error: unknown command WORD`. The program's code, given below, defines every output format exactly.

## The change

Accounts can now hold foreign currencies. The base currency is `USD`; a *currency code* is exactly three upper-case letters `A`-`Z`. Inputs keep the absolute value of every amount below 1000000 and every rate below 1000.

1. **Accounts.** `open NAME TYPE CUR` opens an account in currency CUR; `open NAME TYPE` (as before) opens it in `USD`. A CUR that is not a currency code prints `error: bad currency CUR`, checked after the type and before `exists`. An account in `USD` (also when given explicitly) is a *base account* and prints `opened NAME (TYPE)` as before; any other is a *foreign account* and prints `opened NAME (TYPE, CUR)`. Every amount posted to an account, and its balance, is in the account's currency.

2. **Rates.** New command `rate CUR DAY RATE`. RATE is one or more digits, optionally followed by `.` and one to four digits; it is held as an integer number of ten-thousandths (`1.085` is 10850) and means "one unit of CUR is worth RATE `USD`". The wrong number of arguments, a non-number DAY, a malformed RATE or a RATE of zero prints `error: bad command`; then a CUR that is not a currency code prints `error: bad currency CUR`, and `USD` prints `error: USD is the base currency`. Otherwise the rate is recorded as valid from DAY on (replacing an earlier `rate` for the same CUR and DAY) and the program prints `rate CUR from day DAY: R`, with R as whole units, `.`, and exactly four digits (`1.0850`, `0.0072`, `2.0000`). The lock does not apply to `rate`.
   - The rate of CUR *on day D* is the recorded rate of CUR with the greatest DAY ≤ D; there is none if all its rates start after D. The *latest* rate of CUR is the one with the greatest DAY of all (not the one entered last).
   - *Converting* A cents of CUR at rate R gives A × R / 10000 base cents rounded half away from zero to a whole cent: for A ≥ 0 that is (A × R + 5000) / 10000 with integer division, and the conversion of a negative A is minus the conversion of −A. For example 12.34 at 1.0850 is 13.39, and −12.34 at 1.0850 is −13.39; 0.01 at 0.5000 is 0.01 and −0.01 at 0.5000 is −0.01. A base account's amounts convert to themselves.

3. **Posting.** Each posting now also has a *base value*, fixed when it is posted: its amount converted at the rate of the account's currency on the transaction's DAY (rates recorded later never change it). The checks of `post` are, in this order: all the existing checks up to and including `error: more than one balancing posting`; then, if the `ACCOUNT=` posting is on a foreign account, `error: balancing posting NAME must be in USD`; then, for the postings with an amount in order, the first one on a foreign account whose currency has no rate on DAY gives `error: no CUR rate on day DAY`; then the balance check, now on base values: the `ACCOUNT=` posting gets minus the sum of the other postings' base values as both its amount and its base value (`error: zero posting NAME` if that is 0), and without one the base values must sum to zero, else `error: transaction ID unbalanced by S` with S the sum of the base values. A posting whose amount is not zero but whose base value rounds to 0 is accepted. The total T in `posted ID: N postings, total T` is the sum of the positive base values.

4. **Void.** A reversal posting has the negated amount and the negated base value of the posting it reverses (no rate is looked up, so `void` needs no rate). The checks of `void` are unchanged.

5. **Native amounts.** In `accounts` and in the `close` error `error: account NAME has balance B`, the balance of a foreign account is followed by a space and its currency code (`assets:eur asset 463.13 EUR`, `... has balance -2.00 EUR`); the balance that `close` requires to be zero is the account's balance in its own currency. In `show`, a posting on a foreign account prints as `  NAME AMOUNT CUR (BASE USD)` with BASE its base value (`  assets:eur -36.87 EUR (-40.00 USD)`); base postings print as before. `statement` of a foreign account prints the header `statement NAME (TYPE, CUR)`, the same posting lines (amounts and running balances in the account's currency), and the last line `  closing balance B CUR (book H USD)` with H the sum of the base values of all its postings. For base accounts `statement`, `show` and `accounts` are unchanged.

6. **Current value.** The *value* of an account is its balance converted at the latest rate of its currency (a base account's value is its balance; a foreign account without any rate has value 0). `balance NAME` and `tree` now add up the values of the accounts concerned (each account converted and rounded on its own, then summed), in `USD`. After its usual line, `balance NAME` prints one line `  CUR N` for each foreign currency among the accounts concerned whose balances (in that currency) sum to a non-zero N, in byte order of the code (`  EUR 426.26`). The `tree` output format is unchanged.

7. **Book values.** `trial`, `income` and `journal` work on base values: an account's trial balance is the sum of its postings' base values (`trial` lists the accounts where that sum is not zero), `income` sums base values, and `journal` shows the sum of a transaction's positive base values. Their formats are unchanged.

8. **Revaluation.** New command `revalue DAY` (`error: bad command` with the wrong number of arguments or a non-number DAY). For every foreign account (open or closed), in byte order of the names, take its postings dated DAY or earlier: N is the sum of their amounts and H the sum of their base values; an account where both are 0 is left out. It prints, for each account that is not left out, `NAME N CUR: book H, value V, gain G` with V the conversion of N at the rate of CUR on DAY (there always is one: each of those postings needed a rate on its day) and G = V − H, then `unrealized gain T` with T the sum of the G (`unrealized gain 0.00` when no account is listed). `revalue` changes nothing.

Everything else stays exactly as it is.
