# Implementation Plan: Strings (escapes, raw text, characters, case)

**Branch**: `042-strings` (work on `main`, as for specs 001–041) | **Date**: 2026-11-21 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/042-strings/spec.md`

## Summary

Five small changes that meet in the lexer and the string runtime:

- **Raw strings** are a second way to write a `T_STRING` token (R1): the lexer reads from one backtick
  to the next, the parser takes the text as it is, and everything after the parser sees an ordinary
  string node. The formatter and a new warning (W0102) keep one spelling per text (R2).
- **Escapes** `\r` and `\u{...}` are added in the two places escapes are known: the lexer's
  check and the parser's decoding. The checked literals (`format`, `regex`, `sql`, routes) map a
  position in a literal's value back to the source through one new helper, which also serves raw
  strings (R3).
- **`for c in s`** is a third kind of `for` beside lists and ranges: the checker accepts `str`, the
  compiler emits two new instructions that walk the UTF-8 text by byte offset, and the reference
  interpreter does the same (R4).
- **Case mapping** replaces the ASCII loop in `rt_case` with a generated table of simple mappings for
  the six blocks (R5).
- **Exponents** extend the lexer's float rule; the value comes from the conversion `parse_float`
  already uses (R6).

## Technical Context

**Language/Version**: C (C11, freestanding, no libc), vo, a Python generator for the case table,
JavaScript for the tree-sitter grammar.

**Primary Dependencies**: none new. The tree-sitter parser is regenerated with the dev tools already
in `editors/` (spec 037).

**Storage**: none.

**Testing**: golden cases for every lexical form and diagnostic; `tests/strings.py` for what needs a
reference implementation or size (case mapping against Python's `unicodedata`, 10,000 exponent
literals against Python's `float`, `for c in s` on 10 MiB under a memory limit and against
`chars`); `tests/grammars.py` over all `.vo` files; `tests/diff_engines.py` (its generator gains the
new forms) for the two engines. `make quick AREA=front` and `AREA=text` between edits, `make test`
once; the gate only when asked.

**Target Platform**: Linux x86-64, ARM64, RISC-V 64.

**Project Type**: compiler toolchain.

**Performance Goals**: `for c in s` at least 3 times faster than `for c in chars(s)` and in constant
memory (SC-002); `upper`/`lower` on ASCII text no slower than today (the ASCII path stays a byte loop).

**Constraints**: reference ≤ 15,000 tokens: about 40 are free and the additions need about 110, so
about 70 are trimmed elsewhere without removing a rule (R8). No static table over 64 KiB (the case
table is under 4 KiB). Existing programs keep their meaning: the backtick is not a token today, `\r`,
`\0` and `\u` are errors today, a number followed by `e` is an error today.

**Scale/Scope**: about 150 lines in the lexer and parser, 120 for the loop in four files, 80 for case,
60 in the formatter and warning, 150 in grammars, 400 of tests.

## Order of work

1. Escapes and exponents (lexer and parser only), with golden cases.
2. Raw strings: lexer, parser, the position helper for checked literals, formatter and W0102.
3. `for c in s` in checker, compiler, VM and interpreter; `char_count`, `equal_fold`.
4. The case table and `rt_case`.
5. Grammars and the site highlighter; rewrite escaped strings in examples and tests as raw (SC-001).
6. Reference with trims, catalog, site; three architectures; `make test`; results.

## Complexity Tracking

The constitution's workflow section requires exactly this table for complexity beyond its principles;
the entry below was accepted by the project owner on 2026-11-21 (research R0).

| Violation | Why Needed | Simpler Alternative Rejected Because |
|---|---|---|
| A second string literal form (constitution I: one syntactic form per construct) | Text with its own syntax (regular expressions, SQL, JSON, HTML) is the most common string content in vo programs and the most common source of escaping errors; no set of escapes removes the doubling | Keeping one form leaves `"\\d+"` and `"{\"a\": 1}"`; a builtin taking a file name moves text out of the program and needs an effect. The second form is kept from becoming a second *spelling* by the formatter and W0102: for any text exactly one of the two forms is canonical |
